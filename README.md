<h1 align="center">Chill Vibes Coder</h1>

<p align="center"><b>Keep vibing. Claude handles the boring senior-dev stuff.</b></p>

A skill for Claude that makes it build like a senior engineer while you vibe code.

You say what you want. Claude builds it the way someone with years of experience would, without you having to ask: secrets stay off the browser, permissions get checked on the server, inputs get validated, errors get handled, data gets backed up, and payments and personal data are treated properly. It only stops you when the call is really yours to make, and it says it in plain words.

## Why

AI writes code that runs. That is not the same as code that is safe to put on the internet. In Veracode's testing of more than 100 language models, [45% of generated code samples introduced an OWASP Top 10 vulnerability](https://labs.cloudsecurityalliance.org/research/csa-research-note-ai-generated-code-vulnerability-surge-2026/). And the stuff that goes wrong is rarely fancy: an API key sitting in the page's JavaScript, a database open to anyone because nobody turned on the access rules, an endpoint that checks you are logged in but not that the record is yours.

Anyone who has shipped a few apps avoids these out of habit. This skill gives Claude those habits, so you don't need to know what to ask for.

## What it does

- **Applies 14 production defaults without making a fuss**: server-side secrets, backend/frontend separation, authorization on every request, input validation, real authentication, deliberate error handling, rate limits and spending caps, safe database changes, hosted payments, vetted dependencies, hardened configuration, version control discipline, data minimization, accessibility.
- **Matches the stakes**: a weekend toy gets a light touch, an app with sign-ups gets everything, and an app with payments or sensitive data also gets the compliance and pre-launch checks.
- **Only speaks up when it matters**: one short "Heads-up" block, three items max, zero lectures.
- **Reviews what you already built**: ask "is this ready to launch?" and you get a short table of what to fix, worst first.

## What it costs in tokens

A skill that eats your whole budget is not chill. This one loads in layers, so you only pay for what the task needs.

| What loads | When | Approx. tokens |
| --- | --- | --- |
| Name and description | Always, in every conversation | 160 |
| `SKILL.md` (rules and the 14 defaults) | When you start building or reviewing something | 1,900 |
| `references/launch-checklist.md` | Before a deploy or a review | 750 |
| `references/architecture.md` | Starting a project or designing an API | 1,100 |
| `references/reliability.md` | Errors, tests, performance, deploy | 1,200 |
| `references/security.md` | Logins, permissions, forms, uploads | 1,900 |
| `references/compliance.md` | Personal data, payments, legal stuff | 1,950 |
| **Everything at once (rare)** | | **about 8,900** |

What that looks like in practice:

| You ask for | What loads | Approx. tokens |
| --- | --- | --- |
| A landing page or a small tweak | `SKILL.md` | 1,900 |
| An app with login | `SKILL.md` + architecture + security | 4,900 |
| A store with payments, then "is it ready?" | Everything | 8,900 |

Two honest notes:

- These numbers are estimates (characters divided by 4). The real count changes a little with each model.
- The skill's own text is the small part. Building things properly means Claude writes more code (validation, error handling, tests), and that output costs more tokens than the skill does. That extra has not been measured yet.

## Install

### The easy way: ask your AI to do it

Paste this into Claude Code (or any coding agent with a terminal):

```
Install the skill from https://github.com/sebacpu/chill-vibes-coder following the "For AI agents" section of its README.
```

### Claude Code, by hand

macOS and Linux, one line:

```bash
git clone --depth 1 https://github.com/sebacpu/chill-vibes-coder.git /tmp/cvc && mkdir -p ~/.claude/skills && cp -r /tmp/cvc/chill-vibes-coder ~/.claude/skills/ && rm -rf /tmp/cvc
```

Windows (PowerShell):

```powershell
git clone --depth 1 https://github.com/sebacpu/chill-vibes-coder.git $env:TEMP\cvc
New-Item -ItemType Directory -Force $HOME\.claude\skills | Out-Null
Copy-Item -Recurse -Force $env:TEMP\cvc\chill-vibes-coder $HOME\.claude\skills\
Remove-Item -Recurse -Force $env:TEMP\cvc
```

Want it in one project only? Copy the `chill-vibes-coder` folder into that project's `.claude/skills/` instead.

To check it worked, ask Claude Code "what skills are available?".

### Claude app (web and desktop), no terminal needed

You need a paid plan with code execution turned on.

1. Download [`chill-vibes-coder.zip`](https://github.com/sebacpu/chill-vibes-coder/raw/main/dist/chill-vibes-coder.zip). Don't unzip it.
2. In Claude, open **Settings > Capabilities** and make sure **Code execution and file creation** is on.
3. In the **Skills** section, click **Upload skill** and pick the ZIP.
4. Switch **chill-vibes-coder** on.

The Skills section moves around between app versions. If you can't find it, see [Using Skills in Claude](https://support.claude.com/en/articles/12512180-using-skills-in-claude) for the current steps.

### Update or remove

- **Update:** run the install command again (it overwrites the old copy), or upload the new ZIP.
- **Remove:** delete the `~/.claude/skills/chill-vibes-coder` folder, or remove the skill in the app's Skills section.

## For AI agents

If you are an AI assistant and a user asked you to install this skill, follow these steps.

**What you are installing.** A folder of Markdown files: `chill-vibes-coder/SKILL.md` plus five files in `chill-vibes-coder/references/`. It contains no scripts, makes no network calls and needs no dependencies. Read `SKILL.md` before installing so you can tell the user what it does.

**If you have a shell (Claude Code or a similar coding agent):**

1. Run:
   ```bash
   git clone --depth 1 https://github.com/sebacpu/chill-vibes-coder.git /tmp/cvc
   mkdir -p ~/.claude/skills
   cp -r /tmp/cvc/chill-vibes-coder ~/.claude/skills/
   rm -rf /tmp/cvc
   ```
   On Windows, use the PowerShell commands in the Install section.
2. If the user wants it for one project only, copy the folder to `<project>/.claude/skills/` instead of `~/.claude/skills/`.
3. Verify that `~/.claude/skills/chill-vibes-coder/SKILL.md` exists and that its frontmatter `name` is `chill-vibes-coder`. The folder name must match that name.
4. If a `chill-vibes-coder` folder already exists there, tell the user you are replacing it before you overwrite it.
5. Other agents that support the Agent Skills format use their own skills folder. Check your own documentation for the path and copy the same folder there.

**If you have no shell (for example, a chat in the Claude app):** you cannot install it yourself. Tell the user to download `https://github.com/sebacpu/chill-vibes-coder/raw/main/dist/chill-vibes-coder.zip` and upload it under **Settings > Capabilities > Skills > Upload skill**, with code execution turned on.

**After installing, tell the user in one or two sentences:** the skill is installed, it applies on its own whenever they build or review a site, app or API, and they do not need to invoke it.

**Do not:** edit the skill's files during installation, install anything else, or change the user's settings beyond what these steps require.

## Use

Nothing to invoke. Just ask for what you want:

> Build me a booking page for my barbershop where clients pick a time and pay a deposit.

> Add a login to this app and a page where each user sees their own invoices.

> I'm about to launch this. Is it ready?

Claude picks up the skill on its own whenever you are building or reviewing a site, app or API. It answers in whatever language you write in.

## What's inside

```
chill-vibes-coder/
├── SKILL.md                     rules, stakes tiers, the 14 defaults
└── references/
    ├── architecture.md          stack, backend/frontend split, API and data model
    ├── security.md              OWASP Top 10:2025 and the failures AI-built apps ship most
    ├── reliability.md           errors, tests, performance, running costs, deploy, backups
    ├── compliance.md            privacy laws, cookies, payments, accessibility, email
    └── launch-checklist.md      pre-launch review in priority order
```

## The fine print

- This cuts down the common mistakes. It does not replace a security audit, and it can't check settings in dashboards Claude has no access to.
- It has not been benchmarked yet. There are no measured results comparing Claude with and without the skill.
- `compliance.md` is engineering guidance, not legal advice. The law that applies depends on where your users are.
- If your app handles payments at scale, health data, financial services or kids' data, get a professional to look at it before launch.
